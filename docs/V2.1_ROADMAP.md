# LUDRA HOME V2.1 — Feuille de route frontend

Source : *Dossier technique LUDRA HOME V2.1 — Responsive desktop & mobile* (34 p.).

## Principe de travail : « front prêt, en attente des API »

Chaque écran V2.1 consomme un **service typé** (`src/services/*.service.ts`).
Chaque service a deux modes :

| Mode | Activation | Comportement |
|------|-----------|--------------|
| Mock | `NEXT_PUBLIC_USE_MOCKS=true` (défaut tant que le backend n'est pas prêt) | Données de démo locales (`src/mocks/`), latence simulée |
| Mixte | `NEXT_PUBLIC_USE_MOCKS=mixed` (production actuelle) | Routes livrées par le backend (`src/lib/liveEndpoints.ts`) en réel, le reste en démo |
| Réel | `NEXT_PUBLIC_USE_MOCKS=false` | Appel HTTP vers `NEXT_PUBLIC_API_URL` via `src/lib/api.ts` |

Le backend n'a qu'à implémenter les endpoints décrits dans
[`API_CONTRACT_V2.1.md`](./API_CONTRACT_V2.1.md) avec **exactement** les formes de
réponse indiquées (types de référence : `src/types/`). Aucun changement côté
front ne sera nécessaire, il suffit de basculer la variable d'environnement.

Règles transverses (dossier §6.1, §5, module 16) :
- Aucun prix / quota codé en dur : tout vient de `GET /config/pricing` (mock en attendant).
- Le front masque les actions non autorisées, mais la sécurité est côté serveur.
- Aucun numéro de téléphone dans le HTML/API avant paiement confirmé (module 04).
- Documents KYC jamais publics (modules 03, 07, 11).

Breakpoints : mobile ≤ 767 px · tablette 768–1199 px · desktop ≥ 1200 px (`xl`).

(page `src/app/...`, vue `src/views/...`, composants/services devenus orphelins). Une redirection
permanente vers la nouvelle URL est ajoutée dans `next.config.ts` pour ne pas casser les liens existants.

## Écrans d'authentification

Refondus au design V2.1 : cadre commun `AuthLayout` (panneau d'identité sur desktop, en-tête compact sur mobile). Les formulaires vivent dans `src/views/auth/components/` (`LoginForm`, `RegisterForm`, `AuthUI` : carte, champs à icône, mot de passe afficher/masquer, alertes, bouton) et réutilisent `Field` / `errorProps` / `TextInput` de `components/ui/Form.tsx` (mêmes champs et messages d'erreur que le reste de l'app). L'inscription utilise le même indicateur d'étapes que « Publier ». Anciens `components/auth/LoginForm`, `RegisterForm` et `components/common/ui/{Button,Card}` supprimés. Logique (NextAuth, code e-mail, validations) inchangée.
